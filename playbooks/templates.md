# templates.md — 派工 Prompt 模板

> 讀者：主對話協調模型。用法：複製對應模板，填 `{...}` 空格，用 Agent tool 派出。
> 每份模板已內建三件套（目標動機／驗收條件／回報格式），不要刪這三段。`{}` 內是說明，填完要刪掉。

## 1. 搜尋／盤點（subagent_type: Explore）

```
任務：在 {repo 或目錄} 找出 {目標：所有呼叫點／既有實作／某 pattern 的使用處}。
動機：{主任務是什麼，為什麼需要這份清單——讓你在模糊案例上做對取捨}。
範圍：{包含哪些目錄；排除 node_modules/dist/generated 等}。
徹底程度：{medium＝找到即可 / very thorough＝多種命名與位置都要掃}。

驗收條件：
- 每個結果附 檔案:行號 與一行說明。
- 明確回報「掃過但沒有」的範圍（沒找到 ≠ 不存在，要說掃了哪裡）。

回報格式：條列清單（檔案:行號 — 說明），最後一段：掃描範圍與盲區。
不要貼整檔內容；超過 30 筆就落檔到 {scratchpad 路徑}，回報路徑＋統計。
```

## 2. 實作（subagent_type: code-implementer）

```
任務：實作 {功能一句話}。
動機：{使用者的原始需求與背景}。
規格：
- {輸入/輸出/行為，逐條}
- 參考既有模式：{檔案:行號，指出照哪個既有實作的寫法}
邊界：只改 {目錄/檔案範圍}；不改 {明確排除項}。

驗收條件：
- TDD：先寫失敗測試再實作（有 runtime surface 才需要；trivial 免測）。
- {專案測試指令} 全綠，`tsc --noEmit`（或專案 build）零錯誤。
- 遵守 ~/.claude/rules/（session 已載入）。

回報格式：改動檔案清單（檔案:行號）、測試指令與輸出摘要（passed/failed 數字）、
未盡事項（若有）。不要貼完整 diff。
```

## 3. 重構（subagent_type: code-implementer；大範圍機械性改動用 fast-worker）

```
任務：重構 {目標}，行為不變。
動機：{為什麼重構——壞味道/重複/準備某功能}。
不變式（重構的定義，違反即失敗）：
- 對外行為、公開 API、測試結果完全不變。
- 不順手加功能、不順手修無關的碼。
前置：先跑 {測試指令} 確認起點全綠並記錄數字；起點就紅的話停下回報，不要開始。

驗收條件：
- 重構後同一批測試同樣全綠（前後數字一致）。
- diff 只含重構範圍：{目錄/檔案}。

回報格式：重構摘要（做了什麼、為什麼安全）、前後測試輸出對照、改動檔案清單。
```

## 4. 研究（subagent_type: general-purpose）

```
問題：{要回答的具體問題，一句話}。
動機：{這個答案會用來做什麼決定}。
來源優先序：{官方文件 > repo 內既有用法 > 一手來源（GitHub issue/changelog）> 部落格}。
版本錨定：本專案用 {套件@版本}，答案必須適用此版本，不同版本行為要標註。

驗收條件：
- 每個關鍵論斷附來源（URL 或 檔案:行號）。
- 區分「文件明說的」與「你推論的」，推論要標 [推論]。
- 查不到就回報查不到＋查過哪裡，不要編造。

回報格式：先一段直接回答問題，然後條列證據（論斷 — 來源），最後：不確定事項。
超過一頁就落檔到 {scratchpad 路徑}，回報路徑＋結論三行。
```

## 5. 審查（subagent_type: general-purpose 或 deep-reasoner；必須是沒參與實作的 fresh context）

```
任務：審查 {diff 範圍／MR／檔案清單}，對照驗收條件逐條裁決。
動機：{這批改動要解決什麼；實作者是誰不重要，你沒看過實作過程，這是刻意的}。
驗收條件清單（逐條裁決 通過/不通過/無法判定）：
- {條件 1}
- {條件 2}
審查重點：正確性 > 安全性 > 與 rules/ 的一致性 > 可讀性。不糾結風格偏好。

驗收條件（對審查本身）：
- 每個 finding 附 檔案:行號、問題一句話、具體失敗情境（什麼輸入會壞）。
- 找不到問題也要說明「驗了什麼所以有信心」，不能只回「LGTM」。
- 無法判定的條件明說缺什麼資訊。

回報格式：逐條裁決表 → findings（依嚴重度排序）→ 整體結論（可合入/需修/擋下）。
```

## 通用附註

- 每份模板的回報格式段，派出前補上兩句：「完成後先用 SendMessage 送出報告、再結束回合」；「主對話中途送來的裁決，下次回報時逐項確認已套用」（依據 delegation.md 第四節）。
- 模板派出後對方失敗，按 delegation.md 第五節升降級，**重派時把失敗軌跡貼進 prompt**（原 prompt、輸出、錯在哪），不要裸重試。
- 多個獨立委派放同一則訊息並行送出。
- Agent tool 可傳 `model` 覆寫等級（`sonnet`/`opus`/`haiku`）；**沒有 effort 參數**。
