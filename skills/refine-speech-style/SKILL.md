# 提煉語感回饋 → 更新 communication-style

使用者對「中文怎麼講才自然」給回饋時，把它提煉成**通用規則**，維護進 output style。
使用者給的是症狀（某句話讀起來怪），你要找出病理（背後的通用語感規則）。

## 觸發

- **明講**：「更新語感 style」「記進 style」「這條加進 communication-style」
- **隨口抱怨語感 → 主動提議**：「中文不會這樣講」「這樣講怪怪的」「這句好卡」「不像人話」「像翻譯腔」「這詞很 artificial」
  - 抓到就先問一句：「要不要把這條沉澱進 style？」使用者可拒，拒了就放下。

## 目標檔案

live 檔：`~/.claude/output-styles/` 底下當前啟用的那份（本機是 `communication-style.md`）。
若目錄下有多份，先讀 `~/.claude/settings.json` 的 `outputStyle`——它存的是 style 的顯示名稱
（各檔 frontmatter 的 `name`），拿它回頭對出是哪個檔，不要憑檔名猜。

範本檔：`~/Projects/claude-profile/output-styles/` 下的同名檔。寫入 live 檔後必須同步過去，
並在 claude-profile repo 下 commit——`~/.claude` 不是 git repo，不要在那裡 commit。

規則放哪段：
- **核心原則**：語氣、結論先行、事實與推測
- **回覆結構**：三段式骨架、展開節奏、寫檔門檻
- **解讀程式碼／變更時**：講 code 的順序與重點
- **技術名詞**：英文術語處理
- **標題與小標**：標題寫法、搜尋錨點
- **用詞**：白話化、贅字、行話、假精確詞 ← 多數語感規則歸這
- **篇幅與格式**：長度、保真度、條列、括號、斷句
- **提問方式**：問使用者的方式

## 工作流程

- [ ] 1. **抓反例**：從當下對話找出「讓使用者卡的那句話」，那是規則的反面教材。沒有具體反例就先問使用者是哪句。
- [ ] 2. **提煉規則**：寫成一句通用判準——不是「別講 X」，而是「遇到 Y 就 Z」。同時判斷這是不是**每次都要遵守**的通用語感：是才進 style；若只是這個專案／這一次的偏好，回報「這條偏一次性，不建議進 style」並停手。
- [ ] 3. **去專案綁定**：例子一定要留（few-shot 才可執行），但把綁死專案的詞換成領域中性又具體的載體。判準：換到別的專案還讀得懂。
- [ ] 4. **選段落＋命名**：挑上面的段落，給規則一個粗體小標，格式對齊既有條目：`- **小標**：判準。例：反例 → 改法。`
- [ ] 5. **提案**：給使用者三樣——① 規則一句 ② 放哪段 ③ diff 預覽。等點頭再動。
- [ ] 6. **寫入＋同步＋commit**：Edit 寫進 live 檔對應段落 → 複製同步到 claude-profile 範本 → 在 claude-profile repo 單獨一個 commit（只含這個檔案）。subject 用英文：`style(output-style): <英文摘要>`，中文小標與判準寫在 body。

## 提案格式

```
規則：<一句判準>
放：# <段落名>
diff：
+ - **<小標>**：<判準>。例：「<反例>」改為「<改法>」。
```

## 範例

使用者：「你剛講『這個 churn 的形狀是測試品質不錯的訊號』——中文不會這樣講，把英文塞進比喻裡很怪。」

提案：
```
規則：別把英文術語塞進抽象比喻拼成壓縮標籤，對方要解兩層才懂。
放：# 用詞
diff：
+ - **別把英文詞包進抽象比喻當自創標籤**：把英文術語塞進抽象比喻、拼成壓縮
+   標籤（例：「churn 的形狀」），對方得先拆術語再拆比喻。改法：拆成白話因果
+   句，或先走一個情境再收斂。例：「這個 churn 的形狀是『測試品質不錯』的訊號」
+   改為「這次測試改得很少、又集中在準備資料那幾行；光看它就知道原本測試寫得不錯」。
```
使用者點頭 → Edit 寫入 live 檔 → 同步範本 → 在 claude-profile 下單檔 commit：
`git commit -m "style(output-style): no english terms inside metaphor labels" -m "別把英文詞包進抽象比喻當自創標籤：對方得先拆術語再拆比喻，改成白話因果句。"`

## 注意

- 提煉通用規則，不照抄原話。
- 一次一條；同時冒出多條就逐條提案，不要一次塞。
- 這個 skill 自己也遵守 communication-style：提案簡短、結論先行、少廢話。
